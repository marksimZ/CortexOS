# Phase D2：项目测试任务分片计划

2026-10-29。D1后用户授权继续，并明确选择“先交付任务生成与审核闭环”。本轮为D2a；完成后等待验收，D2b和D3分别进入。

## D2a 本轮范围

从已保存的D1分析版本和用户选择的不可变项目快照，生成最多12项本地只读任务：规范原文复述、代码片段文件定位。规范必须经用户确认并保留有效原文；定位答案来自快照中实际包含所选片段的文件，重复片段允许多个合法路径。无需模型推理或网络，不编造缺陷。

每项绑定分析版本/hash、仓库快照/hash、原文文件/行/hash、只读文件清单、必要上下文、预期答案、评分器版本、资源/时间约束和禁止副作用。使用既有评分器实际检查参考答案通过、空答/错误答案/多余工具调用失败；这是评分规则验证，不是Harness运行或修复实测。人工逐题审阅可修订题目表述和依据，修改追加修订；发布只接受当前修订与人工签名，保存不可变任务集。

复用Phase C的benchmark_generation_jobs、benchmark_generated_cases、benchmark_dataset_reviews、benchmark_datasets；JSON用途标识harness_tasks。普通个性化列表、读取、运行与发布保持personalized用途，缺省旧记录继续兼容。任务集不放入普通模型评测，D3未就绪时没有运行按钮。不新增迁移或第二套Runner。

UI沿用项目适配流程，增加“测试任务”；资料选择、审核列表、版本与原文查看复用当前控件。导入仓库复用既有安全扫描和系统选择器，D2本地用途无需云端密钥；原个性化准入保持不变。错误保留草稿，变更修订使旧批准失效。

## D2b 后续门槛

功能实现、Bug修复、跨文件修改、回归/新增测试、数据库兼容、工具操作及安全审批任务，须先完成Docker安全环境验收，再补充固定失败基线、正确参考补丁、无修改/错误补丁负对照和非目标回归。没有这些客观证据时不发布为可运行编程任务，不执行仓库脚本。

## 验证与交付

先逻辑检查；用途/来源/修订并发/发布信任边界留下必要可运行检查，不跑无关全套单元。执行类型检查、离线Rust检查、桌面构建及真实隔离WebView2流程，截图检查1366×768、1600×900、1920×1080浅深主题；命令、失败与剩余未验收项写入milestone-log。完成D2a后停，不运行第三方Harness、收费模型或安装环境。
