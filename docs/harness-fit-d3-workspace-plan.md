# D3-1：任务副本与独立测试交接

2026-10-30。用户在D3-0交付后要求继续。本片不运行Codex或模型，不新增安装/镜像；实现准备、人工提交修改、收集验证、独立测试及清理的真实闭环，完成后停止验收。

## 范围

首版沿用已审核Python纯函数合同，只复制目标文件的已选函数原文，明确标记“任务范围副本”，不冒充完整仓库。包中仅包含题目、函数签名/类型、限制、原文件路径/行范围与函数原文；examples、标准输出、参考/错误实现和审核评分结果留在数据库/评分侧。原用户文件与固定快照只读。

复用原Docker控制器创建固定Image ID的临时容器，网络none、非root常驻进程、只读root、CPU1/256MiB/PID64、无宿主目录/Socket挂载，只新增2MiB的/workspace tmpfs。可信初始化器仅把文字写入容器，不导入或执行项目代码；目录/题目root只读，允许修改的函数文件可写。常驻最多600秒，不自动重启过期容器。当前不具备真正Agent执行/模型认证能力。

人工修改先保存提交，再由固定文件助手写入、完整盘点并核对题目hash/文件清单/路径/类型/大小/内容hash。拒绝链接、额外/删除文件和越界修改。合格结果保存不可变候选，并按原快照行范围重建完整文件的修改提案；候选包含来源、前后hash和差异。随后先关闭副本容器，再复用原Python评分器在新容器逐条测试，参考/断言不进入副本。测试结果标为人工交接验证，不是Model×Harness成绩，也不回写原项目或旧题库。

## 实现文件与持久化

- `benchmark/harness/workspace.rs`及子模块：复用D3-0已发布任务校验，按harness_workspace用途复用generation_jobs/generated_cases；计划、包hash和候选/观察只追加，状态单独更新。一个数据库同时至多一个未关闭副本；状态/所有权用于停止与恢复，不新建Runner/表或迁移。
- `benchmark/python/workspace.rs`和可信文件助手：复用已有bounded Docker命令、create_args、环境/配置检查、score_owned和按归属清理。前端只提供检查记录ID/hash、人工函数代码和明确确认，不能提供路径、命令、镜像、网络或挂载参数。
- `WorkspaceHandoff.tsx`接入现有执行前检查，独立小组件，沿用Tokens、AppDialog、SelectMenu、状态/表格。准备/停止、历史、函数编辑、原文与修改、单独测试结果及关闭清理；原始依据按需展开，不重排全局界面。
- `db.rs`恢复只把本用途活动状态转interrupted，不自动重跑/恢复容器。普通退出尽力清理本应用记录的副本；强杀或Docker不可用时保留待清理记录，明确提供清理动作。所有容器在创建前记录归属；只清理本任务的名字/label/image/endpoint。

## 验证与门槛

先逻辑审阅。仅为包排除/范围/快照/用途/版本/状态信任边界留下必要检查，不跑无关全套单元。原生独立QA使用已发布真实受控任务及已有Python镜像，实测副本权限/无答案泄漏、人工正确与错误修改、逐条测试、取消/强杀恢复及清理、旧数据保持、三尺寸浅深主题。没有模型、收费云端或宿主仓库脚本。

真实自动编程镜像、模型安全通道、请求数/费用预算、CLI事件和补丁格式转换仍由D3-2独立交付；本片不把前置条件总开关改为可运行。

Docker依据已实际查阅：[tmpfs](https://docs.docker.com/engine/storage/tmpfs/)、[exec](https://docs.docker.com/reference/cli/docker/container/exec/)。tmpfs停止后丢失，因此已收集候选必须先持久化再清理；不宣称tmpfs绝不落到系统交换文件，也不把noexec当作Python代码安全边界。
