# Benchmark 7：导出与独立重新评分

2026-10-28 开始，2026-10-29 交付。用户确认 6.5 验收并授权下一步。本轮完整交付切片 7，按导出协议/安全写入、独立重新评分、UI 接入及验证顺序实施；完成后停在切片 7 验收，不进入真实模型完整验收或发布。

## 依赖与最小方案

复用原批次/用途校验、完整报告、冻结题库、真实执行及 benchmark_evaluations 表。现有个人 JSON 导出未版本化且没有标准入口；新入口统一 JSON/CSV，保留旧命令兼容。现有默认报告会读最新评分，追加重新评分记录前必须明确将它与原评分隔离。

- 新增 report_transfer.rs：生成版本化完整报告和 CSV；记录内容哈希及快照口径；覆盖全部尝试、原评分和追加评分；默认成绩仍是原评分；固定字段剔除结构化凭据。原生保存窗口只接受本机路径，取消不写入，临时文件完整写入后原子提交；拒绝覆盖已存在文件。
- 新增 regrade.rs：只读取已完成的已保存回答，按冻结题库和当前已安装评分器重新评分；先预览输入哈希和范围再确认。每轮结果作为独立 session 追加到原评分表，批次事务整体提交；取消/失败整体回滚。保留源评分 ID、输出哈希、规则/引擎版本。原始报告/运行状态/Token和费用保持不变。
- report_read.rs / scoring_repository.rs：原报告只选原评分；抽出已保存评分计算以复用现有全部评分器。工具字段来自实际 native_tool_calls；Python仍只通过已有Docker策略，不访问宿主机执行。
- 新增 ReportActions.tsx，接入 PersonalizedReport：统一导出、预览/确认/取消重新评分、独立评分历史及逐题结果；沿用 AppDialog 和当前 Tokens。后台任务占用复用全局 TaskSlot，运行/停止/恢复不竞争。个人入口继续通过原准入，标准无需云端密钥。
- lib.rs / build.rs / capability 仅登记对应业务命令；原导出命令代理新协议，无新依赖或数据库迁移。独立记录保存在原追加表的 details.regrade 字段；旧无该字段的记录就是原评分。

导出读取前后校验本连接总变更计数和数据库 data_version；有并发变更则拒绝交付混合快照，提示重新导出。序列化记录不包含凭据配置表；结构化敏感字段另做剔除。用户原文/资料仍可包含私密内容，界面在导出前明确范围；不是对任意自由文本秘密的扫描承诺。JSON为完整可校验协议，CSV为可审阅表格，公式安全前缀规则另记。

## 验收

1. 两类入口可选择 JSON/CSV；保存/取消/存在文件/写入失败保留旧文件与错误，界面只在实际保存后报告成功。
2. JSON解析/内容哈希/全部尝试/费用来源和状态可对账；CSV引号、换行、中文及公式开头正确处理。
3. 预览或取消不写新评分；确认只追加独立结果，输入变化拒绝旧确认；原报告/快照/输出/评分和请求数不变。
4. 工作区、标准/个人用途及批次归属检查；不改聊天、知识或图谱数据。
5. 必要数据库/文件安全专项、类型检查、构建与实际浏览器/原生验证；不运行无关单元套件。原生保存对话框及Docker未能实测时如实单列，不伪造通过。
