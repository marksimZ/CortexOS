# 标准评测：批量运行、停止与恢复

2026-10-27。用户确认修复聊天窗口按钮后，接回原 Benchmark 计划，补齐标准评测的批量运行与恢复。本轮作为原切片 4 的可用交付，结束后等待验收，不自动进入资源采样或更大题库开发。

## 操作

评测 → 标准评测 → 选择本机模型 → 选择 Core 60 v2 题目 → 设置重复次数 → 预览并确认计划。

- 默认先选 2 道短题；可选择全部 60 题、最多 6 个本地模型、每题 1–5 次。计划固定题库版本/哈希、实际模型指纹、题目顺序、重复次数和参数。
- 后端逐模型分组、逐题串行；与日常聊天共用任务锁。界面可切走、重新进入或刷新，运行不会依赖页面继续存在。
- 标准评测不需要云端凭据或使用偏好；后端入口也按标准题库范围核对。云端模型不能通过标准入口绕过确认和费用保护。
- 停止后显示“正在停止”，保存当前部分输出；未发送题目留在队列。恢复需要再次确认，只运行未发送项，不重发中断或失败项。
- 模型已完成输出、但应用中断导致缺评分时，在原评分引擎版本仍匹配的前提下追加首次评分；不改已结束尝试记录，不覆盖已有评分，不产生新模型请求。重跑中断题目需要新建评测。
- 可选授权在切换模型时释放上一评测模型，默认关闭。只处理计划中的明确名单，发送前比对目录及已加载指纹，通过 `/api/ps` 复核；无关模型保持原状。释放结果作为真实评测事件保存。
- 运行和历史复用已有报告：各模型状态、已评分正确率、计划评分覆盖率、执行成功率、题库/选题数量、重复编号、输出、处理记录和 3D 执行过程。Core 60 仍是基础 Smoke Test，没有正式能力排行榜或综合分。

题库 v1、以前的单题接口和历史成绩保留。新批量任务只使用 v2；Python 沿用 Docker Linux 隔离控制器，缺环境时记录运行环境错误，不在宿主机执行。计划中的请求数表示答题调用数，元数据预检和可选释放单独记录。

## 增量实现

没有新增数据库迁移。继续使用 schema 10 的 `benchmark_batches / benchmark_batch_items` 和原有执行、尝试、事件、评分表。

- `src-tauri/src/benchmark/standard.rs`：六个有工作区范围的标准评测命令；题目目录、计划、读取、历史、启动/恢复与停止。
- `benchmark/personalized/batch.rs`：复用串行调度，连接绑定改为可选；标准任务保持无绑定，个人任务继续校验连接。可选选题、重复次数、释放名单默认不改变旧计划序列化。历史按题库身份分开。
- `benchmark/personalized/report.rs`：同一统计实现、两类范围入口；增加可恢复状态、选题/全题库数量、重复编号和实际处理记录。
- `benchmark/dataset.rs`、`repository.rs`：数据库题目读取与批量子运行关联；执行快照记录标准/个人范围及批次 ID，支持正确返回对应页面。
- `benchmark/scoring_repository.rs`：仅允许为已保存完整输出补首次缺失评分，原尝试终态和既有评分仍不可变。
- `ollama.rs`：受控的指定模型释放；固定现有 loopback 策略，不新增通用代理或任意模型管理命令。
- `db.rs`：重启时将停止中的任务也标为中断；`lib.rs / build.rs / capabilities/default.json` 只登记已实现命令。
- 前端新增 `benchmark/StandardSetup.tsx`、`StandardBenchmarks.tsx`；复用 `PersonalizedReport.tsx`、现有状态/菜单/Tokens，调整 `BenchmarkPage.tsx`、共享类型、个人任务停止状态及执行图返回链接。
- 检查新增 `standard_tests.rs`、`tests/standard-benchmark.spec.ts`，在现有 `cloud-connection.spec.ts` 增加窗口位置检查；`playwright.config.ts` 注册专项。

上述路径相对 `apps/desktop/`。本轮没有变更题库内容、知识引擎、数据库迁移历史、云端计费策略或模型下载逻辑。

## 实际验证

- 类型检查和 Windows 调试桌面构建通过，Vite 仍有既有大块提示。
- 必要的数据检查：标准计划/用途范围与重启补评分 2 项通过；原评分存储 4 项通过；个人评测兼容的 11 项通过。检查用于新调度和恢复边界，没有运行无关全套单元测试。
- 浏览器：窗口按钮在 1366×768、1600×900、1920×1080 的顶栏范围、依据栏收起前后坐标保持通过。连接/个人流程合计 8 项中，7 项先通过；旧题库文本选择器因新界面同时包含标题和历史列表而歧义，改用明确标题后单项通过。
- 原生 WebView2：`standard-benchmark.spec.ts --project=desktop` 通过。实际发送至受控本机服务 12 次答题请求：第一计划为 2 模型 × 2 题 × 2 次共 8 次；第二计划停止 1 次后只继续剩余 3 次。观察到最大答题并发为 1；只释放授权的第一个评测模型，无关已加载模型仍保留。
- 同一原生检查验证：无云端密钥、请求快照字节哈希、普通聊天历史和配置不变、标准执行图无需云端准入、部分输出保留、停止项不重发、恢复后评分覆盖率 75% 且已评分正确率 100%。这些来自合成模型响应，不是实际模型能力成绩。
- 已查看三尺寸聊天和报告截图，证据在 `artifacts/standard-benchmark-native-final`；首次检查脚本在异步计划尚未返回前读取 URL，等待实际报告就绪后复验通过，没有伪造结果。

具体命令和构建结果见 `milestone-log.md`。没有运行实际云端、下载模型、安装 Docker、重测系统缩放/读屏或测量 1800 项极限计划的性能。报告目前完整读取本次明细，大计划分页与性能属于后续界面切片；默认从短题、小范围开始。
