# D3-2：首个 Codex 隔离任务

2026-10-31。用户验收 D3-1 后授权继续，并明确批准下载官方 Linux Codex、基于现有 Python 镜像构建专用镜像。模型调用须另行弹窗确认；工具安装授权不覆盖推理。

## 顺序与门槛

1. 固定官方 Linux x64 CLI 版本、包完整性及二进制指纹；从现有固定 Python 镜像离线构建，不读取个人配置或登录，不更改宿主 Codex 安装。
2. 在原容器限制下验证真实 CLI、参数及内层沙盒。无网络、只读根目录、非 root、CPU/内存/PID 限额、无挂载/Socket；CLI 内层权限仍保持 workspace-write 和人工审批语义。沙盒不可用时保留具体失败，不改用全权限、禁用审批或增加容器特权。
3. 前置通过后接受控本地模型通道。容器不能直连宿主服务/互联网；只允许 Rust 对已确认的实际本地模型转发有界请求。凭据不进入容器，参考实现和测试继续留在评分侧。先核实实际协议和可限的参数，不能将配置目标当成已验证限制。
4. 实际推理前弹窗说明模型、唯一已审核任务、请求/时间/输出上限并等待确认。缺少确认时继续独立代码工作，相关调用保持未运行。
5. 复用 TaskSlot、D3-1 的允许文件、修改校验、不可变候选、独立 Python 评分、停止与归属清理。仅新增必要用途记录与精确业务接口，不创建通用终端或新 Runner，不改原任务/聊天/知识。
6. 记录实际 CLI JSONL、模型请求、预算终止、补丁与独立逐条评分；失败和不支持分开。先一项，不进入 D3-3、D4/D5、更多模型或批量对照。

## 验证与停止

先审查实际调用链与权限边界；只执行新增信任边界所需检查、类型检查与构建。原生验证使用独立 QA 数据，截图核对现有三尺寸浅深主题。真实模型未授权/环境阻断的部分明确未运行。安全环境失败时先交付可复现的环境检查、失败证据与修复方案，暂停实际自动编程；不以假事件或放宽权限完成阶段。

官方依据：已实际阅读 [非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[CLI 参数](https://learn.chatgpt.com/docs/cli/reference)、[Provider 配置](https://learn.chatgpt.com/docs/config-file/config-advanced)。文档中的接口须再用固定本机版本核对；ignore-user-config 本身不隔离认证，仍须使用空 CODEX_HOME。
