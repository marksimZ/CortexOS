# Phase D1实施与验收方案

D0见[harness-execution-readiness.md](harness-execution-readiness.md)。静态分析无阻断，按用户授权继续D1，完成后停止。

1. **输入与证据**：系统选择UTF-8 .md/.txt，复用sources::read_selected的本地路径/链接/句柄/2MiB限制，只将副本写入现有RepositorySnapshot；允许选择已有工作区快照。D1仅解析其文档和Repository Profile虚拟JSON证据，不扫描新目录或执行脚本。源文件和每条行号/引用/内容hash可查，删除选择不删除历史快照。
2. **需求画像**：有界确定性关键词/约束线索提取，12类信息及缺失未知项完整展示。所有线索待人工确认，否定/未来/举例不能自动变成硬要求。用户可编辑内容、选择兼容性条件、确认/忽略及设置硬要求；用户补充与文档证据分开记录。不能承诺语义提取完整准确，原文始终可查。
3. **能力目录与匹配**：5个候选、版本化官方资料目录；安装版本/运行认证/未查证能力保持未知。逐条件四态（实测支持/资料支持/未知/不兼容）；本轮不自动产生Harness实测支持。硬性明确不兼容排除、硬性未知等待核实。权重可调；给出已知支持下界、未知带来的上界和证据覆盖，不用未知当答错或已兼容，不与Benchmark成绩合并。
4. **持久化与界面**：0011增量迁移，复用备份/事务机制。单表追加版本，乐观并发；保存计算结果、目录内容/hash、原始需求/用户修改和来源引用。评测增加“项目适配”子页，资料→需求确认→结果，复用现有按钮/菜单/对话框和Tokens，错误保留草稿。历史读取不自动按新目录重算。
5. **验证与停止点**：必要的提取/否定候选/未知/硬过滤/权重、作用域/不可变/并发及迁移备份失败回滚专项；真实development.md原生读取/保存/重开、三尺寸截图、类型/Rust检查和桌面构建。其他聊天/个人评测/知识/图谱按受影响范围检查，不跑无关全套。D2–D5、第三方CLI、付费调用和依赖安装均不进入本轮。

接口集中在`benchmark/harness/`，前端集中在`benchmark/harness/`，目录数据在`src-tauri/catalogs/`。复用现有Provider/Runner/评分/图谱而不创建第二套运行系统；D1只保存Document Fit，Task Performance与Model×Harness Fit明确未实现。
