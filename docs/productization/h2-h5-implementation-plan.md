# Phase H2–H5 实施计划

H1 已完成前端命令边界、导航历史、样式和交互验收，证据见 [H1.4 验收](../frontend/h1-4-acceptance.md)。[G5 验收](../optimization/phase-g5-release-validation.md)记录了真实标准评测的资源保留阻断，[H0](../release/h0-blockers.md)已交付单次释放选项并完成有界复测。正式安装身份升级、多屏与 DPI、签名及许可履约继续由 H4 跟踪。安装器解包完整性证据见 [H0 Windows 验证](../release/h0-windows-validation.md)。

| 阶段 | 落地顺序 | 验收依据 |
| --- | --- | --- |
| H2 数据管理 | 资产盘点；格式与一致性快照；预览、验包、暂存和重启恢复；凭据边界；空间统计与知识导出 | 两个独立数据目录完成往返；包含历史评测与知识版本；验证损坏、容量不足、旧 Schema、工作区隔离和中断恢复 |
| H3 可靠性与诊断 | 先以现有 TaskSlot 和各领域记录核对排队、取消与中断语义；再做错误注入、脱敏诊断导出和固定负载采样 | 验证取消作用域与恢复幂等；诊断报告通过敏感数据样本审查；提供相同配置的 P50/P95、采样时长和未测环境 |
| H4 发布工程 | 核对正式标识与版本配置；在隔离 Windows 环境验证真实旧版升级；以官方能力实现本地签名更新演练；核对许可和交付材料；构建 Dry Run | 隔离环境通过安装、升级、凭据及数据保留；校验安装包内容、SHA-256、更新签名与 Authenticode；形成 Go / No-Go 记录 |
| H5 产品体验 | 走查首次启动、知识与评测流程；完善可跳过的本地引导；从 TaskSlot 与执行事件接入任务中心；按需帮助及三类场景验收 | 基础使用可全程本地完成；保留个性化评测准入；任务状态及跳转可复现；如只有内部走查则标明 |

备份格式独立于数据库迁移编号，H3 诊断只引用版本和结果摘要。H4 的升级测试复用 H2 隔离样本与恢复流程。H5 任务中心消费 H3 的状态投影，不另建调度器。每个阶段使用独立提交序列，完成后等待验收。实际本地模型验证需逐批确认，正式发布需另行批准。
