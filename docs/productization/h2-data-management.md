# H2 数据管理与迁移

## 数据资产盘点

| 数据 | 位置及代码依据 | 用户原始数据 | 持久保存 | 可重建 | 可能敏感 | 导出 / 备份 |
| --- | --- | --- | --- | --- | --- | --- |
| 工作区、会话与消息 | SQLite migration 0001、0008 | 是 | 是 | 否 | 是 | 结构化备份 |
| 执行记录与请求快照 | SQLite migrations 0001、0004、0006、0023 | 执行证据 | 是 | 否 | 是 | 结构化备份，随对应评测报告导出部分证据 |
| 知识、历史版本与审核 | SQLite migrations 0002、0014、0015 | 是 | 是 | 否 | 是 | 结构化备份及知识 JSON / Markdown |
| 导入的文件文本、来源版本和引用 | SQLite migration 0007；原始文件在用户选择的位置 | 是 | 已导入副本须持久保存 | 原文件内容可能已变更 | 是 | 随知识导出关联副本及行号，原文件由用户保管 |
| 分段、词语和向量索引 | SQLite migrations 0012、0013、0021 | 派生数据 | 保留现有可用索引 | 分段和词语可重建；向量需对应模型 | 是 | 随 SQLite 快照备份 |
| 关系、版本、布局及图谱快照 | SQLite migrations 0003、0005、0016 | 关系与布局由用户编辑 | 是 | 历史及手动位置无法完整重建 | 是 | 结构化备份，知识导出含关系 |
| 标准与自建题库、版本和评分 | SQLite migrations 0008–0010，Rust benchmark 模块 | 标准题内置，自建题由用户审核 | 是 | 历史版本和评分不可重建 | 是 | 现有评测 JSON / CSV、结构化备份 |
| 项目配置、快照、补丁与评测记录 | SQLite migrations 0010–0011，Rust Harness 模块 | 项目代码、审核及执行证据 | 是 | 否 | 是 | 现有项目及评测导出、结构化备份 |
| 活动容器和容器内工作副本 | Docker；任务标识与已提交产物保存于 SQLite | 活动副本可能含未提交编辑 | 数据库内的已提交产物持久保存 | 容器可另行重建；未提交编辑需先保存 | 是 | 任务记录进备份，容器与镜像由 Docker 管理 |
| 模型配置、预算、连接和隐私授权 | SQLite `app_settings` 与 migrations 0018–0025 | 用户配置 | 是 | 否 | 地址等可能敏感 | 全量配置及工作区所属配置进备份 |
| 用户偏好、个性化题库和使用资料 | SQLite migrations 0009–0010 | 是 | 是 | 否 | 是 | 结构化备份；已运行批次可用评测导出 |
| 应用偏好和本机草稿 | WebView2 localStorage，`preferences.ts` 与 `draft-store.ts` | 草稿是 | 是 | 否 | 可能含未提交文本 | 随备份携带已知应用字段 |
| Windows 凭据 | `cloud/vault.rs`、`cloud/runtime_connections.rs` | 密钥 | 由 Windows 保存 | 按连接重新绑定 | 是 | 由 Windows 保管 |
| 界面缓存及恢复副本 | `storage.rs`、`storage/recovery.rs` | 界面资源缓存为派生数据 | 按需 | 是 | 可能与页面相关 | 按 G2 流程核验和回收 |
| 模型文件、镜像及已导出报告 | Ollama、Docker 或用户选定的任意路径 | 用户导出可能是唯一副本 | 外部持有者负责 | 模型、镜像取决于上游可用性 | 是 | 依赖在清单中呈现 |

实际数据库路径由桌面运行环境提供。开发与发布应用的凭据隔离。备份归入用户选择的本机位置，可包含未加密的私有内容。SHA-256 校验文件损坏，不提供发布者认证。

## 备份、恢复与导出

1. 「设置 → 本地数据 → 备份与恢复」选择整个应用或当前工作区，预览后使用 Windows 对话框选择保存位置。后台执行 SQLite 一致性快照。工作区导出将归属明确的行写入新库，从保留的知识重建全文索引。已经发布的 Core 60 共用题目按版本保留，自建题库按归属筛选。
2. \`.cortexbackup\` 格式 1 使用 ZIP，含 \`manifest.json\`、\`cortexos.sqlite3\` 和 \`ui.json\`。清单记录应用版本、迁移版本、备份范围及编号、工作区、创建时间、文件字节与 SHA-256、外部依赖。校验按固定文件名提取，逐文件复核大小及哈希，并核对迁移校验和、实际 SQL 结构、SQLite 完整性和外键。压缩写入结束后才发布目标，已有同名文件保持原样。
3. 打开备份后显示校验结果及范围，勾选确认后暂存。工作区与目标同编号时拒绝合并。全量恢复按确认范围替换数据。重启时先取得数据目录锁，再校验暂存数据和可用空间，保存恢复前的安全备份，并对候选数据库执行迁移和完整性检查。Windows 在同一卷替换数据库。未完成的候选保存阶段允许重启复核，切换完成后以数据库中的恢复编号避免重复执行。
4. WebView2 从待完成记录应用草稿和偏好，确认保存后写入恢复历史。全量恢复前的草稿与偏好基于确认时捕获，数据库安全副本基于实际重启时捕获。确认恢复后应结束其他编辑并立即重启。恢复历史可定位安全备份，也可重新打开该包恢复。不经确认的备份不能触发数据切换。
5. 云端连接只归档配置。打开设置时对照当前数据库路径、工作区、连接编号和服务地址检查 Windows 凭据。缺少密钥时可对原连接编号重新绑定，避免重新搭配已保存的运行方案。绑定过程只写 Windows 凭据，刷新模型列表或能力验证由用户单独操作。
6. 知识导出提供 JSON 或 Markdown。JSON 含条目、历史版本与审核、有效日期、来源版本和引用行号及关系版本。Markdown 提供阅读版及相同来源编号，保留正文与版本对应关系。评测 JSON / CSV 沿用现有报告入口并保存模型、数据集、评分和运行环境记录。

## 空间管理

- 存储清单测量 SQLite / WAL / SHM、迁移备份、恢复前备份、暂存与界面缓存。知识正文、已保存资料、向量及全文索引、评测及项目副本按可核对的内容字段统计库内字节，已包含在数据库文件大小中。
- 沿用缓存核验、确认预约、退出复查、移动至备份和撤销操作。同盘归档保留原件。清理旧缓存副本前会要求再次确认，核验实际缓存已经重建、备份身份仍匹配且没有等待中的恢复。清理按记录执行，结果显示清理文件的字节数。索引、证据及用户原始数据属于受保护项。Ollama 模型与 Docker 镜像仍由各自环境管理。
- Docker 中 /workspace 使用临时内存文件系统。应用的磁盘清单显示已经保存的项目副本与运行记录字节。运行中的容器内存副本大小须从获准的容器观测获取。
