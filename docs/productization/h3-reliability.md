# H3 任务可靠性与本机诊断

## 任务状态

| 跨模块状态 | 判定依据 | 应用重开后的处理 |
| --- | --- | --- |
| 等待 | TaskSlot 已登记，还没有获得资源 | 返回原计划，由用户再次确认启动 |
| 执行中 | 已持有资源，业务模块已开始或准备开始 | 恢复数据库记录，核对请求是否已经发出 |
| 停止中 | 已发送取消，资源仍在收尾中 | 按模块核对是否完成清理 |
| 已完成 | 模块登记的正常终态 | 从原记录读取 |
| 失败 | 模块登记失败或需要清理 | 展示已知原因，保留已有结果 |
| 已取消 | 模块确认正常停止 | 保留生成片段、评分或任务证据 |
| 已中断 | 异常退出，或请求结果无法确认 | 保存中断记录，避免自动重发 |

实时计数从共享 TaskSlot 和独立存储 TaskSlot 读取。历史状态从各业务表投影。评测中的未运行、分项评分、Harness 待清理和云端费用未知等领域语义仍保留在各自界面与记录中。

关闭窗口时同时取消并等待任务队列和存储扫描。对于已经开始的本机恢复记录或清理操作，等待其释放资源后再关闭。Docker 容器继续按原有实际任务归属清理；异常退出后的恢复沿用现有历史记录，不自动发出模型请求。参见 [任务队列](../../apps/desktop/src-tauri/src/tasks.rs)、[关闭和恢复入口](../../apps/desktop/src-tauri/src/lib.rs)、[SQLite 中断处理](../../apps/desktop/src-tauri/src/db.rs)。

## 错误处理

- 鉴权失败应检查密钥，模型权限不足应检查连接和权限。预算或额度耗尽时应核对额度。临时限流按既定预算规则有上限地重试，服务异常可稍后手动重试。
- 网络中断时保留已入库的内容；请求结果未知时先检查处理及计费记录。应用启动过程只核对记录和状态。
- 本机模型连接问题保留实际错误状态，云端选择仍要求按现有运行方案确认。索引构建失败或取消时保留已有索引。容量不足的恢复保护沿用 [H2 证据](h2-backup-restore-test.md)。
- 本机生成接口的 HTTP 429 和 5xx 保留对应状态。界面和报告只保留预定义提示与状态码。

## 使用本机诊断

在「设置 → 关于 → 本机诊断」选择「检查运行状态」。可查看应用与数据库版本、本机后端、Ollama 与 Linux Docker 可用性、两组任务数、近 24 小时的分类错误以及整机资源。云端连接为已保存的检查状态。Ollama 使用版本接口，Docker 使用本机 context 和系统类型信息。两者均为只读探测。

「导出诊断报告」会重新采样，并在用户选择的位置保存 JSON。报告按字段白名单构建，仅包含预定义状态、数值、计数和时间。模型标识、请求、报告正文、IP、文件路径、工作区名称、GPU 序列标识和 Windows 凭据没有读入报告。错误时间和数量为汇总值，云端请求统计包含实际发送的重试次数。GPU 数值为整卡数据，可受其他程序影响。参见 [诊断实现](../../apps/desktop/src-tauri/src/diagnostics.rs)。
