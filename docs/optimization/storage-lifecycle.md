# G2 存储与资源生命周期

## G2.1 存储清单

在「设置 → 本地数据」选择「读取存储清单」。总数为应用实际读到的文件逻辑字节，包括数据库、WAL、SHM、应用升级备份和默认 WebView2 界面数据。库内资料或向量的内容字节已包含在数据库文件内。逐文件磁盘分配量来自 Windows 文件元数据，读取受限时显示未测得。逐文件分配量无法直接表示可回收空间，例如多个文件名可能引用同一份磁盘分配。

| 清单项 | 检查范围与依据 |
| --- | --- |
| 主数据库、WAL、SHM | 由当前应用数据库路径确定，按文件测量 |
| 应用升级备份 | 只检查数据目录顶层符合升级备份命名的普通文件 |
| WebView2 界面数据 | 默认应用数据目录内的 `EBWebView`，读取文件元数据。自定义位置标为未测量 |
| 已保存资料与历史 | 从只读 SQLite 连接统计文件版本、知识引用、处理快照、知识快照版本及评测结果引用 |
| 查找索引 | 统计配置关联的本机索引和云端索引、向量条数及 FTS/向量内容字节 |
| 项目任务 | 统计已记录的项目资料、审核和修订结果。任务计划中的容器编号是登记信息，运行状态需向 Docker 验证 |
| Ollama、Docker、外部文件 | 仅显示库中可核对的配置或引用数量。原始文件和导出目标由用户保管 |

前端传入读取编号，路径由 Rust 根据应用运行目录决定。清单扫描复用任务槽的取消机制并使用独立槽，聊天和评测可继续运行。目录扫描最多检查 20000 项及 24 层，跳过链接、目录联接及特殊文件。读取失败或达到上限时显示已测下限。读取编号只用于当前扫描，停止后保留上一份报告。独立 SQLite 连接在只读事务中取引用，释放快照后再测文件。取消在目录条目与数据库查询之间检查。

清单里的引用是按类型统计的已登记关联。回收资格需要进一步核对每一项，尤其是索引关联、快照哈希、容器归属和已保存补丁。用户原始数据、历史证据和数据库备份进入保护范围。

## G2.2 回收预览

在「设置 → 本地数据 → 预览可回收内容」查看缓存状态、文件位置、管理方、文件大小和当前使用情况。余量通过 Windows 查询拟用备份位置所在磁盘。备份位置暂定在应用数据目录下的 `storage-recovery`，预览只读取元数据及 SQLite 引用，不创建备份目录。存在链接、目录位置异常或余量查询失败时显示未核实或未测得。已测缓存大小是文件逻辑大小。实际腾出的空间需要在回收完成后另行测量。

预览向正在运行的 WebView2 查数据目录。仅当它与 CortexOS 默认位置一致时，才读取 `EBWebView/Default` 下的 `Cache`、`Code Cache`、`GPUCache`。候选目录及其上级须为普通本地目录。扫描遇到链接、特殊文件、读取错误或上限，该项保持保护。空目录与位置未核实分别显示。WebView2 的网站存储、设置和登录数据均受保护。缓存可由 WebView2 重建，退出应用后仍须复查使用状态、路径和身份。[WebView2 数据类型](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/winrt/microsoft_web_webview2_core/corewebview2browsingdatakinds) [Windows 磁盘余量接口](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw)

知识与来源版本、历史评测、报告、审计记录、升级备份、原始文件和外部模型始终受保护。库内索引及项目任务暂按清单显示已登记引用。索引的逐版本引用、重建条件及任务产物归属还需核对，当前均在保护范围。读取开始或结束时检测到活跃任务会标记在预览中。

## G2.3 确认与恢复

展开预览里通过核对的缓存，选择「移到备份…」，确认后一次预约一项。应用在下次启动创建 WebView2 之前，持有数据库已有的单实例锁，核对上次登记的界面进程已退出、路径及目录身份一致、目标位置无冲突，以及同盘余量可读。文件由 Windows 按已核对的目录句柄移动。找不到目录、链接、占用、位置变化和跨盘的情况写入结果，需重新确认才能发起新预约。[WebView2 进程退出](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2environment5) [Windows 目录重命名接口](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info)

「缓存操作记录」显示待下次启动、已撤销、已移入备份、已恢复或未完成。待处理的预约可以撤销。恢复时保留已重新生成的缓存副本，再把旧备份放回。如果第二次移动失败，会尝试放回原缓存，无法放回时仍保存双方文件并展示原因。操作在移动中断后按文件身份核对已完成的动作。记录与文件位于 `storage-recovery/<预约编号>`，保留原预约和结果。备份同盘移动的释放量为 0，永久移除备份需要另外定义确认和恢复边界。

## 后续验收顺序

**G2.4 任务资源协调。** 在现有任务槽和用途约束上增加资源需求、冲突状态、等待与取消。保留默认串行行为，分别验证本地模型、索引、评测、容器及云端预算边界。

各步骤的实际命令和结果记录在 [里程碑](../milestone-log.md)。
