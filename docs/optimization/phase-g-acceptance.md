# Phase G 验收记录

## G2.4 调度

索引、标准和个性化评测、项目编程验证、项目副本、工具单题和组合实验使用同一串行队列。排队状态按任务范围读取，取消仅作用于仍在等待的请求。取得资源后继续执行各业务原有的计划、版本、权限和环境校验。应用重启后，未启动请求需要重新确认。已开始的任务沿用原有中断恢复和清理记录。

固定回环的原生联测中，标准评测占用任务槽。跨工作区取消及重复启动被拒绝。组合实验等待状态在 127.64 毫秒内被轮询发现，取消从点击对应 IPC 到原请求返回共 5.71 毫秒。各为一次样本，包含测试 IPC 和轮询延迟。评测释放资源后，旧修订的编程验证先退出，索引随后发出 1 次固定向量请求。等待中的索引请求为 0。未测真实模型加载次数、显存和 Docker 运行资源。

另一次真实 Docker 的固定回复组合实验在启动前采得整机物理内存 16,898,142,208 字节、整卡显存占用 1,534,066,688 / 8,585,740,288 字节及 GPU 利用率 13%。这是同时运行其他程序时的一次快照，无法据此计算 CortexOS 的峰值或节省量。

初次回归发现宽批次超时、非活动桌面的关闭与文件选择自动化不稳定、任务来源定位器仍匹配旧文案，以及迁移测试沿用旧版本号。重点场景拆分复跑，独立桌面关闭使用应用按钮，Win32 对话框取消以现有的归属检查做回退，历史迁移断言跟随现有迁移列表。迁移会重新构建 FTS5 索引，内部编码可变化，因此升级断言比较持久数据和实际检索结果，回滚仍比较完整快照。组合实验首次恢复场景超过 5 秒的测试等待，改为 25 秒后全场景通过，产品超时保持原值。
