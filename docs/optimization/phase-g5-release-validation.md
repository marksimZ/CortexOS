## 性能与 G0 对照

同一台 Windows 机器、原非活动桌面脚本、相同测试库和视口。应用启动数据来自调试 custom-protocol 进程，包含 WebView2 和 bootstrap。首轮采样与图谱测试时间重叠，整机负载与 G0 有差异。差值仅用于发现可复测热点。

| 指标 | G0 P50 / P95 | G5 P50 / P95 |
| --- | ---: | ---: |
| 新 WebView profile 启动，3 次 | 722.42 / 1130.76 ms | 948.29 / 969.97 ms |
| 已用 profile 启动，5 次 | 707.66 / 724.36 ms | 995.92 / 1363.99 ms |
| 空闲应用进程树 RSS，10 次采样 | 438,652,928 / 439,480,320 字节 | 424,235,008 / 443,150,336 字节 |
| 空闲应用进程树 Private Bytes | 276,365,312 / 277,049,344 字节 | 269,694,976 / 273,301,504 字节 |
| 应用与空闲 Ollama 的 CPU，整机归一化 | 0.00% / 2.11% | 0.00% / 2.61% |
| 词语 RAG 预览 IPC，30 次 | 6.90 / 8.10 ms | 9.94 / 13.25 ms |
| FTS5/关系固定 RAG，5 次 | 107.01 / 118.51 ms | 126.89 / 176.35 ms |
| 千节点固定图谱 rAF 间隔，300 次 | 7.00 / 7.10 ms | 7.00 / 7.10 ms |

千节点图谱在 headless Edge 1600×900、DPR 1、固定 IPC fixture 下测量。G5 最大帧间隔 14.3ms，五轮空闲均新增 0 次绘制。`requestAnimationFrame` 间隔是页面帧观察，不是 GPU 单帧渲染耗时。Windows 刚开机的真正冷启动未测。

之后使用同一测量脚本串行运行旧 G0 和当前 G5 程序，两个批次分别存于 `artifacts/phase-g5-g0-control` 与 `artifacts/phase-g5-quiet`。G0 先跑，未重启或清理缓存。旧 G0 副本的新 profile P50 复测为 2235.26ms，波动大，不以首跑顺序归因性能。旧 profile 启动 P50/P95 为 756.19/937.46ms和 805.00/972.29ms。词语预览为 7.58/8.72ms 与 9.33/12.23ms，G5 仍较慢。FTS5/关系为 122.19/144.71ms 与 144.56/152.14ms。G5 应用空闲 RSS P50 444,661,760 字节，G0 复测 441,360,384 字节。两批整机空闲 CPU P50 分别为 21.88% 和 30.95%，故需在可控负载下确认是否存在版本回退。

实际 GPU 聊天端到端为 9478.78ms，约 500ms 一次进程采样、约每秒一次整卡显存采样。期间整卡峰值 4,782,555,136 字节（4.45 GiB），当批空闲阶段最高 1,691,353,088 字节（1.58 GiB）。这两个量含系统与其他程序。监控未确认独立 runner 的完整 RAM 占用，不把 Ollama 服务工作集当成模型 RAM。G0 同模型为 CPU，样本 6 次，因此不计算 GPU 相对速度提升。

独立图谱并行请求端到端 6534.49ms。24 节点相机操作在请求开始后约 1.6 秒窗口采样，单独和并行各得 230 个间隔，P50/P95 均为 7.00/7.10ms，最大 7.10/7.30ms。并行整卡峰值 4,661,968,896 字节，结束后 Ollama 已加载模型为 0。只支持这一短窗口和固定小图谱的结论，不能外推到大型图谱、长输出或不同硬件。两项合计向真实 Ollama 转发 2 次，约定上限为 3 次。

固定回环标准评测占用、三工具实际 Docker 接力与重启合计 56 个采样。CortexOS 与 WebView2 工作集峰值 474,857,472 字节，Private Bytes 峰值 323,514,368 字节。该窗口的整机 CPU 峰值 76.52%，整卡显存最高 1,731,198,976 字节，系统可用内存最低 1,551,798,272 字节。此窗口同时涵盖评测、工具和应用重启，不能拆出各任务的独立峰值。进程树统计不含 Linux 容器内部分项。原始数据在 `artifacts/phase-g5/queue-resource-resources.jsonl`。

单独运行固定回复标准评测完整回归，包含串行模型组、停止恢复、独立评分、导出和报告界面，1 条通过，总 48.8 秒。99 个样本中应用及 WebView2 的 RSS 峰值 668,135,424 字节、Private Bytes 峰值 788,283,392 字节、整机 CPU 峰值 52.17%、整卡显存峰值 1,840,250,880 字节。采样覆盖整个测试，其中包含报告及保存对话框。这一峰值不能代表真实标准评测的模型峰值。

## 安全与分发

- 正式 NSIS 生成脚本的应用负载仅主程序，无额外资源和 sidecar 声明。生产 dist 27 个文件无 source map、数据库、源码扩展名、`.env` 或 token 文件。正式主程序针对常用 GitHub token 和 PEM 模式扫描命中为 0。未独立解包压缩安装器，因此结论限于生成脚本、实际打包输入及抽样模式。
- Windows 目标的 Cargo 解析图 320 个包，含主程序。已安装 npm 运行依赖 169 项。Rust 常见许可 MIT/Apache-2.0，另有 5 项 MPL-2.0 声明。npm `webgl-constants` 的元数据缺少许可字段，随包 LICENSE 是 MIT。仓库有单独的 Codex seccomp 许可，尚未找到项目根许可或安装包第三方声明汇总。分发材料仍需确认。
- Docker 配置核对无网络、只读根、非 root、cap-drop、内存/CPU/PID/时限、无 Docker Socket 及宿主目录。队列复验观察到运行、中断后的归属清理。未逐个镜像重复所有反向边界测试。
- Windows 随机测试凭据保存、重读、替换及删除通过。固定云端回环认证与连接复用测试通过。旧库迁移回滚、备份恢复测试通过。检查本轮报告和日志，未匹配相应测试凭据或抽样私钥标记。未审计所有历史日志，也未使用真实云端凭据。

## 正式环境人工验收

1. 使用专门的 Windows 测试 VM 或独立 Windows 用户，新建快照。核对上表 SHA-256 与 Windows 签名状态。按系统提示处理签名，使用组织允许的方式启动安装。
2. 全新安装正式包。首次启动，确认主窗口、设置和本地工作区，退出再打开。记录 Windows 版本、WebView2 版本与首次启动时间。
3. 在第二个干净快照中安装真实上一个发行版。新建合成聊天和两版知识，保留一份评测历史。凭据验证使用专用测试项。退出应用并备份数据库、相关文件与可恢复凭据材料。升级后核对工作区、历史、证据定位和连接状态，再核验 SQLite 完整性、外键与迁移备份。需要访问真实云端时先单独确认供应商和预算。
4. 在隔离快照人为制造升级目标不可写。确认升级提示失败，恢复权限后从备份重试。比较升级前后记录、数据指纹以及备份可打开性。
5. 在 1366×768、1600×900、1920×1080 下测试边角缩放、拖拽、最大化和还原。两个显示器分别设置 100% 和 150%，来回拖动，检查点击坐标和弹窗关闭位置。
6. 卸载时使用默认保留数据选项，确认程序和快捷方式移除、测试数据保留。显式删除数据的分支只在可丢弃的 VM 另作测试。
