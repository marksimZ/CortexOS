本计划依据 [架构审计](architecture-audit.md)、[存储实测](storage-report.md)、[性能基线](performance-baseline.md) 和 [依赖审计](dependency-audit.md)。G0 完成测量与规划。用户授权 G1 持续推进，每个切片完成后先自检并记录对照。下表是验收目标，实际成绩另见 [里程碑](../milestone-log.md)。

## G1 统一对照及验收

每个切片保留原实现的基线和固定 fixture，记录代码/构建/数据版本、窗口/DPR、调用参数、首轮与稳态、样本数、P50/P95、CPU、RAM、可获得的 GPU 数据及缺失原因。启动、IPC、图谱、长会话沿用本轮脚本，改进辅助计时口径时同时重测原版本，避免混比。

验收至少包括：输出与顺序一致、原始/审计数据不变、请求数或资源指标达到该切片目标、对应业务操作可用。若改善仅在安装体积而非运行速度，分别呈现。由新增风险决定必要的定向测试，不以全量单元测试替代原生操作验证；也不为低影响文档变化运行测试套件。

## G2：Storage Lifecycle Manager

具体范围与切片验收见 [存储与资源生命周期](storage-lifecycle.md)。

先实现只读清单和引用关系，再提供预览，最后单独实现经用户确认的回收。入口放在现有设置的数据/资源区域，默认只显示容量与可解释的分类，不自动删除。

| 数据类别 | 所有权与默认策略 | 回收资格 / 恢复 |
| --- | --- | --- |
| 用户原始资料、知识、附件 | 用户所有，永久保留 | 从缓存回收排除；任何删除走原有明确业务操作 |
| 来源快照、执行请求、历史评分、任务审核与审计证据 | 版本不可变、绑定用途和引用 | 历史引用仍可打开；不能以“旧版本”判断过期 |
| FTS / 向量 / 可重建查询索引 | 应用派生数据，记录生成器与内容版本 | 无活动读取、无有效 profile/快照引用；先在副本验证重建，保留恢复 manifest，事务切换 |
| 临时任务目录 / 容器 | task ID、用途、创建者、路径、容器标签 | 终态、无运行进程、无未导出修改、无证据引用；路径检查及白名单，失败保留可诊断状态 |
| 下载、开发缓存、WebView cache | 分开记录工具版本、hash、保留期限 | 验证不含 cookie/登录资料、正文或证据；先可恢复隔离/保留窗口，再确认永久回收 |
| 外部模型 / Docker 镜像 | Ollama / Docker 及用户共享资源 | 本应用只读统计和说明引用，不擅自删除系统资源 |

清单合同包含：稳定资源 ID、绝对路径、类型、用途、逻辑字节、可获得的物理字节、测量时间、所有者、引用列表、活跃状态、可重建方式、保护原因、恢复位置和扫描错误。大目录扫描可取消、分批，不锁住 UI 或长期持有 SQLite 锁。

建议复用当前任务槽和文件权限帮助函数。引用检查至少涵盖数据库关联、运行状态、报告/导出清单、模型 profile、快照 hash 和保留中的 patch。删除前再次核对路径、标识、文件变化和引用；新出现引用时撤销预览资格。跨卷“移动到恢复区”需要空间预算，不能当作瞬间安全操作。

G2 验收顺序：只读扫描结果可核对 → dry-run 列出逐项保护/回收理由 → 用户确认指定清单 → 失败/中断/重复操作 → 恢复后历史入口可打开 → 再次扫描容量。收益用真实回收的物理空间和恢复成本报告，不把 36.59GB target 或整个 7.05GB Docker VHDX 直接当作可回收目标。

## G2：Resource Scheduler

在 TaskSlot/Lease 上增量扩展资源声明，保留现有默认串行执行，不一次替换各领域控制器。

- 任务声明用途、工作区、CPU/本地模型/Embedding/Reranker/Docker/云端连接需求及可取消阶段。调度器负责占用、排队、取消和释放，领域模块继续负责参数与结果。
- 模型以实际指纹及设备偏好识别；本地推理和向量计算遵守每批授权与显存保护。估算不完整时显示未知，不凭空承诺可并行。
- 云端并发同时遵守提供方速率、费用预留和隐私规则。停止后结算实际用量，保留未知账单状态。
- Docker 保留非 root、无网络、资源上限、无敏感挂载/Socket 及专用过滤器。调度等待不能扩大权限或转宿主执行。
- 3D 保持按需渲染和用户可中断相机，纳入前台交互预算；不通过关闭用户正在查看的图谱取得“性能提升”。

验收：互斥冲突可见、队列不会静默饿死、取消等待不误取消其他任务、异常和重启能释放归属资源、现有单任务行为一致。比较并发冲突数、排队与取消延迟、加载次数、RAM/VRAM峰值，而非仅展示一个队列界面。

## G3：架构收敛

保持模块化单体，按职责逐项核对后提取：

| 顺序 | 收敛对象 | 复用边界和验收 |
| --- | --- | --- |
| 1 | Provider Registry / HTTP 传输 | 复用现有能力合同与连接目录；本地/云端认证、隐私和错误语义分别保留 |
| 2 | Job Lifecycle | 先画状态/恢复矩阵，抽一致的申请、终态和清理；保留 Benchmark 数据集绑定及 Harness 计划 hash / 容器所有权 |
| 3 | Execution Trace | 统一摘要、分页及导航；原事件来源、用途、不可变快照继续可读，不重写历史 |
| 4 | Data Access | 固化 workspace/purpose 查询合同和可见性，缩小持锁区；连接池只有实测收益足够时再引入 |
| 5 | Cache / Permission | 共享身份、引用与恢复合同；权限在文件、密钥、网络、知识和容器访问入口继续强制执行 |

每项提供至少两个真实调用方、重复代码/行为证据和可量化收益。职责不同的代码继续分开；不为“统一”引入微服务、消息队列、通用脚本执行器或配置驱动框架。没有收益的候选保留现状。

## G4：完整回归与发布验收

以下均为后续验收清单，本轮没有将它们标为通过。使用隔离库和固定 fixture；需要真实模型或收费 API 的项目单独确认，未运行的项目保留原因。

| 范围 | 核心操作与证据 |
| --- | --- |
| AI 对话 | 新建/恢复会话、输入法、Markdown、流式生成、停止、中断恢复、自动滚动/翻阅；核对输出和真实执行轨迹 |
| 知识与版本 | 新建/编辑/审核/对比、来源版本导入/停用、生效日期、冲突、快照/分支；历史引用和当前检索各自正确 |
| RAG | 词语/向量/关系/重排、混合策略、索引更新失败与回退、引用行范围、无依据及冲突；固定检索结果和评分版本 |
| 3D | 现有知识图和执行图入口、节点/来源定位、邻域、分页、历史和返回定位；相机可中断、空闲绘制和大规模资源 |
| 标准 / 个性化 Benchmark | 数据集 hash、隔离用途、状态分母、批量/停止/恢复、单题详情、重新评分和导出；不改历史评分 |
| Harness Fit Lab | 资料/任务审核、工具预检、原生工具对象、隔离工作区、修改及独立测试、并排实验、恢复、证据导出 |
| 本地 / 云端 | 能力发现、模型/连接切换、不可用、超时、限流、错误回显、预算和隐私；回环与真实网络结果分别注明 |
| 密钥 / 权限 | Windows 凭据存取与删除、无明文落盘/导出/日志、不同 endpoint 不串凭据；前端不直接访问受限资源 |
| Docker | 引擎缺失明确不可运行；无宿主回退、无网络/敏感挂载/Socket、CPU/内存/PID/时间/输出上限、终态清理及反向保护 |
| 数据兼容 | 逐版本旧 fixture 到当前迁移、迁移前备份、故障恢复、旧题库及评分可读、purpose/workspace 隔离；对副本做完整性/外键检查 |
| 桌面与交付 | 1366×768、1600×900、1920×1080，原生 WebView2、标题栏/拖动、覆盖层关闭、键盘导航和 150% 缩放；截图与人工检查分开 |

每个核心流程将功能通过与性能改善分别记录。性能对照达到目标且兼容性无回退后才进入交付；环境阻断不改写为成功。真实模型使用性能测试不能代表模型能力排行榜，固定回环通过不能代表真实 Docker 或真实云端通过。
