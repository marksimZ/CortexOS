# D3-1：任务副本与独立测试交接

2026-10-30，按[本片方案](harness-fit-d3-workspace-plan.md)实现。当前是人工交接验证，Codex、模型、完整仓库脚本及组合实验均未启动；D3-0的旧检查保持原快照，不能因本片准备了函数副本就把Agent执行总条件改成已就绪。

## 操作

评测 → 项目适配 → 4.测试任务 → Codex执行前检查 → 选择已保存的任务检查 → 任务副本与独立测试。

1. “新建任务副本”核对检查hash、已发布任务/审核/来源，使用该任务固定Image ID。副本仅包含task.json和project/原路径下的已选函数原文，明确为任务范围副本，其他原文件内容不复制。
2. task.json只包含题目、签名/类型、允许路径/原行范围及约束，不包含examples、标准输出、参考/错误实现、审批评分结果或凭据。原任务和快照保留数据库中，宿主原项目不读写、不挂载。
3. 题目及目录只读，只有已选函数文件允许原地改内容。编辑后点击“收集修改并独立测试”，确认实际要运行本地测试。确认与代码保存在同一事务；错误、停止、中断后可查看已提交内容。
4. 固定文件助手写入文字并盘点文件：拒绝链接、非普通文件/硬链接、多余/缺失文件、错误内容hash或权限。整个过程不导入或执行项目代码。
5. 通过校验后保存不可变修改提案：原文件、原行范围、原文/修改、前后hash及按原范围重建的完整文件。范围之外的字节保留，修改不写回原项目，不执行git apply。
6. 先清理副本，再用现有纯函数评分器在新的受限容器逐条测试。查看实际通过/未通过/取消/环境或评分错误及逐条观察；成绩标为人工交接，不加入Model×Harness、标准或个性化成绩。
7. 关闭副本保留已提交修改及结果，明确放弃未提交编辑。每个数据库最多一个未关闭副本；同工作区其他检查下的未关闭副本有查看/关闭入口，其他工作区继续严格隔离。

## 环境与生命周期

复用原Python Docker控制器的本地端点检查、create_args/配置校验、固定镜像、CPU1/256MiB/PID64、只读root、非root常驻进程、cap-drop ALL、no-new-privileges、无网络和宿主挂载/Socket。仅增加2MiB /workspace tmpfs；可信初始化器在容器内以root写入文字并设只读权限，不加cap、不运行用户代码。文件助手每次最多5秒，继承原64KiB输出限制；函数24KB、传输131072字节。题目/目录root只读，目标函数文件内容可写，不支持新建、重命名或需要临时同目录文件的原子替换操作，真实CLI兼容性仍后置。

常驻命令固定等待600秒，容器不自动重启。该时间只用于本片没有Agent的临时编辑会话，不是未来不可信Agent的完整预算机制。本轮核对固定配置，不用配置检查冒充已等待/测量完整600秒。tmpfs停止即丢失，候选先落库再清理；不宣称tmpfs绝不进入操作系统交换文件。独立评分仍按原控制器单断言5秒/整题60秒及原输出限制执行。

正常关闭应用会取消活动任务、等待结束并尽力清理本应用记录的副本；重复关闭在清理期间继续等待。Docker不可用等失败保留待清理，允许退出。强杀后重开标记interrupted，不自动恢复/重跑；用户清理已记录归属的遗留容器后再新建。创建前持久化所有者和名字，清理核对本地端点、名字、owner label和镜像，不做全局prune。

评分沿用现有纯函数规则；固定测试能验证其覆盖的行为，不构成完整语义正确性、全面副作用证明或漏洞不存在的保证。本片隔离与修改范围校验不等于第三方编程工具的自动化兼容验收。

## 文件与存储

- `src-tauri/src/benchmark/harness/workspace.rs`、`workspace/{records,package}.rs`：计划/审核绑定、工作副本生命周期、允许包、文件验证、修改提案、独立评分及停止清理。
- `src-tauri/src/benchmark/python/workspace.rs`、`workspace_io.py`：复用bounded Docker命令与既有配置/评分/清理，只提供固定创建及文件传输，不提供终端。
- `src-tauri/src/{lib,commands,db}.rs`、build.rs、capabilities/default.json：四个精确业务命令、正常退出清理及本用途恢复；没有通用文件或执行权限。
- `src/benchmark/harness/WorkspaceHandoff.tsx`、ExecutionPreflight.tsx和harness.css：独立折叠组件、确认、状态/历史、代码和固定关闭的修改查看弹窗，沿用当前设计。
- 检查代码：既有validation/tests.rs扩充事务/范围/状态/恢复边界，package局部包/观察/原文范围专项；`tests/harness-workspace.spec.ts`独立原生Docker项目与配置。

schema仍11，复用generation_jobs/generated_cases，purpose=harness_workspace。计划/version/包hash不可变，所有环境、容器归属、提交、候选、逐条评分及清理观察只追加；状态单独更新。后台worker沿用TaskSlot，不重建Runner。历史发布、D3-0检查、聊天、知识及普通评测查询不读写本用途。没有迁移、依赖或锁文件变化。
