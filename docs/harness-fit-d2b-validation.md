# D2b-1：编程任务真实对照与人工发布

2026-10-30。本轮承接D2b-0环境验收和已交付的草案，完成已有Python纯函数变更任务的验证、审核及不可变发布。没有接入第三方Harness或仓库构建，不宣称D2所有任务类型已实现。

## 用户流程

入口：评测 → 项目适配 → 4.测试任务 → 编程任务草案。

1. 保存草案，选择“读取本机Python镜像”。仅列举本机python仓库下3.13标签、且元数据版本符合要求的Linux镜像，最多8个；不自动下载。执行时再次检查实际镜像及Python握手版本，固定Image ID。
2. 点击“开始容器验证”，确认当前修订、镜像与三份代码将执行；沿用已有无网络/挂载、非root、只读root、CPU1/内存256MiB/PID64、单断言5秒/单实现60秒、输出64KiB的策略。
3. 依次执行参考实现、固定快照原代码、错误实现。页面显示已实际保存的组数，可停止并等待清理；切页后可回到历史查看。失败、停止、中断与尚未运行分别保留。
4. 三组结果表优先展示，逐条输入/输出、原始观察、准入条件及环境/hash按需展开。预期应当失败的原代码/错误对照显示“未通过（符合预期）”，不将它们冒充成功实现。
5. 全部条件满足后，由用户核对题意、来源、用例及结果，填写审核人并批准，发布任务新版本。修改草案后须重新验证，旧结果不能批准新修订。
6. 已发布版本只读，保留原代码/来源、当时用例、验证与审核记录；可嵌套打开来源。验证参考代码不等于运行模型或Harness，发布物的taskExecution仍为Not Run。

## 验证条件

| 条件 | 当前实现 |
| --- | --- |
| 参考实现 | 状态Passed，所有断言均记录并通过 |
| 原代码 | 状态Failed，至少一个target失败，所有regression通过 |
| 错误实现 | 状态Failed，至少有一个正常返回但未通过的用例；单纯语法错误/超时不能充当有效错误对照 |
| 完整性 | 三组均记录全部断言；逐条索引与容器数量符合合同 |
| 版本绑定 | 草案revision/hash、三份code hash、实际Image ID、策略及评分引擎版本匹配 |
| 清理 | 所有实际创建容器有归属记录、已清理，无待处理容器 |
| 人工批准 | 当前最新修订、具体验证ID/hash、审核人和明确批准均满足；发布版本并发检查通过 |

“功能需求”与“报告的故障”由用户明确填写，不自动编造Bug。当前要求原函数存在且有可保留的非目标行为；新空函数、跨文件补丁/仓库测试/数据库兼容任务继续单独切片。对照通过说明这些固定用例能区分三份实现，语义与覆盖是否充分仍须人工审核。

## 实际记录与兼容性

新增`benchmark/harness/programming/validation.rs`，复用既有generation_jobs/generated_cases，以purpose=harness_programming_validation独立记录计划、环境、逐容器归属及逐组评分；不重建Runner。原harness_programming_drafts的草案修订和保存时静态结果保持原样。候选记录只追加，计划/内容SHA256校验。

发布复用datasets/reviews，purpose=harness_programming_tasks。每个草案可发布单任务集多个版本，Case绑定发布version并重新封装hash；manifest保存当时草案、实际验证、审核人及taskExecution。普通聊天、标准/个性化题库及旧Runner不读取此用途，不加入普通benchmark_cases。schema仍11，历史迁移不改。

新增7个精确业务命令：读取本地Python环境、读取验证历史/详情、开始/停止验证、清理本次遗留容器、人工发布、读取发布版本。没有通用终端或任意文件操作。前端复用已有AppDialog、SelectMenu、FitStatus和CSS Tokens，验证区为独立组件，不重排全局页面。

评分引擎升级为`core60-runtime-2.2`，用于标识本轮修正的Docker准备/启动阶段取消分类。取消发生在Python握手之前也保存Cancelled；保留原安全与答案规则。历史2.1评分和D2b-0补验结果不会重算或覆盖，Core60 v1/v2文件字节不变。

## 中断与清理

创建前记录容器名字/验证所有者，实际容器附加com.cortexos.validation标签；正常执行后仍由原控制器清理。应用恢复只把本用途validating标为interrupted，不自动重跑。意外强杀时尚存的容器须回到该验证点击“清理本次遗留容器”；清理逐个核对本地端点、记录的名字、所有者标签及镜像，拒绝处理其他归属。成功或已不存在都追加真实清理记录，不改写旧执行结果。

强制杀掉应用会同时终止其宿主超时控制器；因此本轮通过实际强杀/重开/清理验证恢复路径，不能宣称此时宿主计时器仍在运行。容器本身的CPU/内存/PID/网络/挂载限制保持；用户完成清理前该次记录不具备发布条件。

## 验收与停止点

必要信任边界检查覆盖用途、工作区、未验证/伪造/旧修订批准、原版本不可变和中断恢复；共享Python专项覆盖所有CLI阶段握手前取消，以及既有类型/输入/逐断言规则。真实独立WebView2+Docker检查覆盖三组控制、两版人工发布、失败参考、停止、强制退出及恢复清理；原草案与D2a流程另作必要回归。实际命令、失败修复、最终截图和结果见[里程碑](milestone-log.md)。没有运行无关全套单元、模型、云端或新模型下载。

本轮停止在D2b-1首个可验证任务闭环，供用户验收。更广的仓库任务和D3 Adapter另行推进；不把本次受控示例当成真实模型/Harness性能或正式能力排行榜。
