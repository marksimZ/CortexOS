# Phase E／F 统一实施计划

## E0 架构

`工作区 + 查询 + 版本范围 → 路由 → 词法／语义候选 → 按稳定 ID 去重与融合 → 可选精排 → 上下文预算 → 生成 → 引用验证与用量记录`。

- 保留 SQLite、已批准知识、原文版本、关系版本与执行历史。索引属于可重建数据。E1 首先索引已批准知识版本，E2 再建立 Markdown 和代码片段索引，原文来源 ID 及行范围从早期数据迁移保留。
- 向量索引标识包括工作区、Provider、模型、版本指纹、维度、L2 归一化和索引版本。向量用小端 `f32` BLOB 保存，查询侧核对维度、值和范围。首版对有上限的索引扫描；只根据实际性能需求评估近似索引或部署依赖。
- E1 批量构建在锁外调用已选本地服务，提交前重读可用版本。新索引完整写入后才切换。取消、服务不可用、维度变化与输入改变均可重建。旧对话维持当前词法路径；用户启用且存在适用索引的真实请求才调用向量模型。预览用词法候选，发送时再执行所选策略。接入依据见 [Ollama Embedding 接口](https://docs.ollama.com/api/embed)。
- 相同知识版本的多个召回结果合并，RRF 初值 `k=60`；分别保留词法、语义及融合排名。有效、已批准、工作区及来源停用过滤统一执行；最后按现有真实请求预算保留内容。E1 可选择本地词项覆盖度作为轻量精排。F0 后允许独立选用模型精排。
- 用既有 `execution_runs`、`execution_events` 与 `context_snapshots` 关联查询、候选、筛选、精排、最终上下文、模型调用和用量；事件按实际执行写入，保留旧版读取路径。标明字节估算与服务实际 Token。运行元数据只保存模型引用和允许范围，凭据留在 Windows 安全存储。

## 顺序和验收

| 步骤 | 交付与验收 |
| --- | --- |
| E0 | 审计、共享流水线与索引合同。检查本地数据库、当前入口及旧版本兼容边界。 |
| E1 | BM25、Ollama 向量、RRF、去重、当前知识过滤、可选轻量精排。用固定响应覆盖模型切换、坏维度、失败恢复、数据隔离及旧聊天。真实本地调用单独确认。 |
| E2 | 文档与代码分片、结构和范围、子片召回、预算内父级展开；覆盖 UTF-8、版本重导与停用。 |
| E3 | 当前、历史及实验分支，显式事实日期和废止关系。验收过去与当前答案不同，拒绝跨工作区和停用来源。 |
| E4 | 按真实版本化边做 1–2 跳检索、冲突导航及依据化知识簇摘要。验证方向、边状态、循环上限和证据范围。 |
| E5 | 轻量查询路由，支持明确禁用、词法、混合、精排、图与版本策略。用包含私有知识的问法和空问题检查。 |
| E6 | 在回答依据及原执行图增加检索检查，界面显示实际步骤和入选原因。原生检查不同尺寸与主题。 |
| E7 | Benchmark 固定知识、题目、评分器和对照策略。确定性检索与引用指标先验证；LLM Judge 有实际模型、口径和独立授权。 |
| F0–F2 | 将 E 阶段实际使用的 Embedding 合同与现有两种生成调用扩展为能力接口。实现本地模型能力、资源释放、云端目录与已支持协议。模拟验证各能力及凭据隔离。 |
| F3–F5 | 工作区可保存 Local／Cloud／Hybrid 模型组合、隐私范围、路由、超时、限额、费用预算和安全回退。验收默认私有、失败不外传、凭据不落普通日志。 |
| F6–F7 | 同一执行记录生成资源与费用报告，Benchmark 做完整组合对照及导出。真实和模拟分别呈现。 |

每步做真实可执行的定向检查，记录命令、失败和兼容性。两个阶段最终统一验收。重大安全、数据迁移或 Provider 阻断须保留现场结果并单独报告。

## 已落地的边界

- E1 当前索引上限为同一工作区 2000 项、每项最多 8192 UTF-8 字节。超过单项上限的已批准知识仍可参加词法查找。应用不下载模型。真实向量质量、延迟、内存和显存占用待实测。可选精排使用关键词覆盖度，执行快照同时保留精排前的融合排名。索引切换与维度失配已通过固定响应验证。
- E2 已从已保存的文件版本产生父片与子片；版本、内容哈希和原文件行列共同标识片段。行列从 1 开始，内部坐标末端为右开区间，引用的原文行号含首尾。Markdown 支持 ATX 标题和围栏代码，围栏中按 Rust、Python、JavaScript 的常见声明提取符号。纯文本按段落和字节上限切分。路径使用资料文件名，原始绝对路径留在本机来源存储。独立代码文件继续遵循当前文件选择范围。
- E2 对与原文一致的已批准长摘录直接检索文件片段，优先在预算内发送同节父片。超预算时发送小片或跳过，引用保留发出的内容与原文行号。编辑后的知识正文按现有流程使用。独立源码文件、PDF 等载体仍在后续导入范围。

### E2 索引迁移方案

迁移 13 将经确认且与来源摘录一致的长知识切为文件片段。FTS5 词项和向量使用同一片段 ID。保存工作区、知识版本、文件版本、父子位置、章节和符号。批准或停用时更新词法索引，向量通过显式重建追平。按片段融合候选后，同一知识版本只保留一个最佳命中，再按预算读取父片或命中子片。人工选取与编辑过的知识继续使用完整正文。

迁移前备份，事务内重建 FTS5 并保留既有文档向量和执行记录。未切分的知识可以继续使用现有向量，已切分的知识立即获得片段词法召回，在重建后获得片段语义召回。新索引使用独立版本标识，重建失败时保留上次索引。验收覆盖纯语义片段、原文边界、版本审批、来源停用、工作区隔离及旧索引读取。

### E3 版本范围与验收顺序

1. 先实现固定知识快照。明确区分快照的记录时刻、知识批准时刻和事实生效日。固定快照保存工作区与明确的知识版本及来源版本，审批事件提供可核验依据。快照跨工作区拒绝读取，停用来源在新请求里始终排除，过去的请求快照保留。
2. 再接事实生效、失效日期和替代关系。日期为可空值，既有记录显示未知。在带事实日期的查询中区分已知有效、已知失效和日期未知。单个版本的创建时间只说明记录何时写入。当前默认范围只用有效且已批准知识。
3. 实验分支复用固定快照的版本集合。分支对所选版本的改动只影响实验，工作区默认查找与生产审核记录独立。按已有版本化关系识别显式冲突，记录两端版本与边的证据。历史范围使用该快照确定的边版本。
4. 先用隔离库验证同一问题在当前与历史范围给出不同资料、日期边界、替代关系、停用、跨区、实验隔离及执行记录。界面入口接通后单独验收。

E3 第一片使用迁移 14，新增不可改的知识版本日期和快照表。事实日期采用本地日历日，生效日当天可用，失效日当天起排除。指定日期只检索有明确日期且当日有效的已批准版本，同节点取版本号最高的匹配项。固定快照保存当时的当前知识版本，后续检索仍检查文件停用。两个显式范围先用本地词项检索，保留 E2 的原文坐标与预算。当前范围保持已有混合检索能力，过滤未生效或已失效的版本。会话历史只复用同范围的已完成请求，显式范围的版本集合变动时重新隔离历史。

E3 第二片使用迁移 15。实验分支保存基准快照和逐项替换的版本，只能替换基准中已有的知识，可明确选用草稿。每次保存产生独立分支，生产审批、生效版本、索引和旧快照继续各自管理。普通快照冻结反驳关系的修订号，分支沿用基准的反驳关系。迁移对已有快照按保存时间回填可确认的关系。按事实日期查找时，使用当前登记的关系并标注依据。

现有反驳关系可在预算内补入另一方，只检查原始候选的一跳。发送内容和执行记录准确列出双方是否入选。替代关系以同一知识的先后审批为准，在版本历史和回答依据列出；跨知识的“修订”边继续表达图谱关系。代际记录用于审计，历史版本仍可在特定范围中用于查找。

按事实日期查找时，先选当日已开始生效、日期有记录且版本号最高的已批准版本，再检查失效日期。若该版已失效或来源停用，该知识从本次候选排除。旧版不会因为新版到期而自动恢复使用。

当前范围只复用仍符合权限与有效版本的历史轮次。已过期、被接替或来源停用的知识曾参与旧轮时，保留旧轮记录并从新模型请求排除该轮。

### E4 图谱检索与知识簇

在对话资料区可选开启沿知识关系查找。以手动选用和文本检索排在前面的资料为起点，最多六个起点和两跳。依照已保存的边进行双向查找，保留边本身的方向和版本，反驳边只作为路径终点。节点须属于所选工作区、版本和来源范围。排序、去重及上下文预算继续执行，记录路径、文件版本、截断状态与资料是否入选。

迁移 16 将现有快照关系表扩展到全部已登记关系，保留已冻结的反驳记录。旧快照对新增关系类型按早于保存时间的关系修订回填，实验分支继承基准快照的边。知识簇概览对所选范围的已登记关系计算相连资料组，列出知识和文件数量、关系类型及可打开的代表资料。摘要由数据库生成，超过读取上限时标明部分结果。

### E5 查询路由

由 Rust 在发送和预览时按相同规则选策略。会话关闭自动查找时仍可使用手动资料。用户指定事实日期、快照或实验分支时，使用该范围内的版本。未指定范围、未手动选用资料且未要求图谱的情况下，只有规则表中的独立问候、致谢或无可查文字输入会跳过自动查找。带数字或分隔符的独立 ASCII 标识符优先用 FTS5。其余问题在有可用索引时使用混合查找，按当前工作区设置决定是否按词语覆盖度重新排序。问题中出现关系路径、依赖链、冲突来源等明确短语时叠加图谱查找，也可以沿用开关每次沿关系查找。

预览只执行本地词语或版本范围查找，标明发送时预计使用的方式。发送时保留所选策略、实际查找方式和降级原因。已有历史记录按原字段读取。使用固定向量及临时 SQLite 验证私有问法、工作区隔离、范围优先、禁用、空内容和索引变化。

### E6 查找过程检查

回答依据、处理记录和执行图共用同次运行的查找详情。按需展开实际步骤与耗时、候选来源、原文版本和范围、记录的词语与语义排名、合并排名、重排得分和选用原因。被预算或条数淘汰的候选也保留来源位置。已选资料显示请求快照中的文字，可从有效引用跳回同一条回答。服务收到请求与只准备资料分开标示。实际 Token 使用服务报告的整次用量，单条资料显示实际文字字节数。旧记录沿用当时已保存的数据。

### E7 固定检索对照

在评测页提供独立题库和策略 A/B。每次在内存数据库导入固定文件版本、知识版本、时间和关系，通过现有检索及资料装配路径运行。当前策略使用题库基准日，按日期策略可使用题目指定日期。混合策略使用固定向量，引用与答案规则使用同一段固定回复回放。记录每题实际候选和最终资料的版本、评分依据、题库与知识内容指纹、评分器版本。真实生成与模型判分单独取得运行授权。

迁移 17 追加按工作区存放的不可更新评测报告。一次对照完整计算后写入一条新记录，已有表和历史成绩继续原样读取。验收覆盖迁移失败回滚、快照及题库一致、策略可区分、重复运行、工作区隔离和评分口径。

首版 `cortex-rag-v1` 含 11 份示例文件和 9 道题。两侧使用 8192 的上下文设置和同一知识库、题目与固定回复。当前策略在题库基准日计算，按日期策略优先使用题目写明的日期。固定向量以资料编号和题目的固定向量输入构造，便于检查混合和重排代码。每题保留实际算法、候选排名、装入的证据版本、图谱关系和引用核对。

- Recall@5、MRR@5 和二值 nDCG@5 使用入选前的前五名候选与标准知识版本计算。无标准资料的题不计入这三项及各类召回率。
- 已选资料的准确率和召回率以实际装入请求的知识和版本计数。资料效率是相关资料正文的 UTF-8 字节占全部资料正文的比例。查找用时来自本机执行阶段，关闭检索时不产生用时。
- 固定回复的引用准确率检查实际引用编号对应的资料版本及原文。引用召回率按成功引用的不同标准资料计数。原文支持率检查预置的提取式陈述是否出现在对应引用文字中。拒答准确率检查固定回复是否按预期拒答。检索冲突准确率使用实际查找记录，覆盖无冲突的题。
- 总表对适用题目取算术平均并显示题数。空分母对应未适用。固定回复及固定向量的结果用于回归检查。真实模型的生成质量和模型判分需要独立授权批次与明确评分规则。

### F0 模型能力接口

向量、重排和生成各自有请求与输出合同。向量合同校验批量维度及数值，重排以输入位置对应得分，生成保留本地分块和云端完整结果两种传输方式。Ollama、现有云端凭据通道和本机词语重排分别接入。现有执行记录继续保存实际供应商、模型与历史协议字段。F1 扩展本机目录与资源管理，F2 扩展云端能力并保留逐能力验证结果。

### F1 本机模型运行和资源

从本机目录和模型详情读取已安装模型、能力声明和上下文上限，从正在运行的模型接口读取实际加载情况。设置可指定仅用 CPU 和回答后的模型保留时间，缺省 0 秒。新对话把这些设置写入实际请求快照，已冻结标准评测使用各自原计划。向量继续仅用 CPU，单批完成后释放。手动卸载由任务锁保护，核对目录和已加载指纹，收到回执后再读取状态。卡片和任务进度继续使用既有设置折叠区与状态文本。[Ollama 已加载模型接口](https://docs.ollama.com/api/ps) · [Ollama 模型释放行为](https://docs.ollama.com/faq#how-do-i-keep-a-model-loaded-in-memory-or-make-it-unload-immediately)

### F2 云端模型能力

现有 C1 连接继续服务个性化评测。统一运行所需的连接按工作区和连接 ID 从 Windows 凭据存储读取，目录只返回公开信息。目录声明、用户参数和实际调用验证分别记录，能力未知保留未知。OpenAI 和 Gemini 的向量适配复用统一的维度校验。兼容服务按明确的 HTTPS 地址和协议选项接入，各能力独立确认，并仅向保存的服务地址发送相应凭据。[OpenAI 向量接口](https://developers.openai.com/api/reference/resources/embeddings/methods/create) · [Gemini 模型目录](https://aistudio.google.com/api-reference/models) · [Gemini 向量接口](https://aistudio.google.com/api-reference/embeddings)

迁移 18 保存工作区连接、目录、验证结果和用户登记费率。Windows 凭据与服务商、地址及启用的兼容协议绑定。兼容服务的对话按 Chat Completions 协议解析，重排只用于明确启用了兼容 `/rerank` 的连接，并核对结果输入位置。[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) [Rerank 响应格式](https://docs.cohere.com/v2/reference/rerank)

### F3 工作区运行方案

为每个工作区保存多套方案以及一个当前方案。回答、向量和重排分别选择模型，向量和重排可关闭。当前方案为空时沿用原有本地配置。云端目标以连接 ID 和模型 ID 定位，按所选环节验证能力。切换方案只影响后续请求。运行时在发送前重新解析工作区归属、连接和能力，记录本次实际方案与目标。云端方案接入真实任务前必须明确可发送的数据范围并校验。

云端回答的确认绑定方案版本和当次允许的知识版本。授权按连接保存，云端请求默认处理本次问题。用户可选择附加手选知识，或在本机检索此连接已获授权的生效版本。发送前检查当前版本、来源状态和常见密钥格式。执行记录的请求快照保留实际请求体，发送事件记录连接、模型及数据类型。

云端索引按工作区、连接、模型和维度定位，构建仅读取当次确认范围内的已授权片段。查询重用相同向量空间，在本机完成向量比对。云端重排只接收此连接被授权的候选，对余下候选保留本地排序。两个环节都要把实际发送的数据范围和耗时写入记录。

### F4 路由与费用限制

统一运行的付费用途共用云端请求记录。发送前按工作区、任务和连接核对最近 24 小时费用、单次任务费用和每分钟请求数，在同一事务内预留估算额。费用按登记的美元费率和输入量估算，结果以服务报告的 Token 核算。失败及中断保留预留额；超过上限时停止发起新请求。仅服务明确响应限流时按配置重试，默认为 0，最多两次。准备回答期间可停止查找。

任务路由使用明确的工作区方案和成本或质量偏好，选择结果随请求保存。备用模型沿用已经审批的信任范围。切换目标会记录新请求及切换原因，自动切换遵循费用限制和当次授权。

普通问答和知识问答各有首选及可选的费用对照方案。优先费用时按设置的容量上限和登记费率比较，保留未知费用状态。模型尚未返回文字时，可自动尝试配置好的本机备用模型一次。原模型请求与备用请求分开保存，分别保持不可变。

### F5 隐私与安全

发送及重试前复核当次知识版本，自动查找、建索引和重排都按目标连接授权。手选资料由用户当次确认并核对有效版本。发送防护拦截常见密钥格式，支持工作区启用邮箱和连续 11 位大陆手机号的检查。云端回答把资料固定作为待分析的数据处理，应用仅接受模型文本并不执行其中的指令。用量与发送记录保存结构化元数据。

### F6 费用和本机资源

按工作区、提供方、模型、能力汇总实际请求，用量未知的字段显示未报告。费用来自费率估算，未记录用量的尝试保留原预留额。工作区预算涵盖最近 24 小时，面板另可查看最近 7 天的请求。系统 CPU 和整张 GPU 可单次读取，主机指标按采样范围显示。本机向量记录服务报告的输入 Token 与生成数量，回答记录单次用时和可取得的系统 CPU 区间平均值。

### F7 固定知识与模型组合对照

在隔离的固定语料上运行两组已选方案。冻结知识版本、题集、评分规则、检索策略、模型设置和能取得的模型指纹。各环境使用独立副本，以同一规则计算检索、回答与引用指标。付费调用沿用工作区预算，实验前明确发送内容和模型。历史完整保存，导出包含计划、实际执行记录、覆盖率、用量、费用与资源读数。

阶段验收证据集中在 [Phase E 交付报告](phase-e-delivery.md)、[Phase F 交付报告](phase-f-delivery.md)及[迁移兼容性](phase-ef-migrations.md)。固定回放与模型组合对照分别保存。
