## 统计对象与状态

一个逻辑项是模型身份×数据版本/题目ID×实验条件×重复序号；尝试是一次实际发送。代码断言、工具步骤、对话回合不能冒充独立题目；重试不替换首次结果，不挑最高分尝试。

每条记录分别保留：

- **模型能力**：supported / unsupported / unknown，附advertised或probe证据、模型digest、检查时刻。一次格式错误不是证明模型不支持。
- **运行条件**：系统模块、隔离环境、权限、评分器可用性；缺Docker或缺代码评分器不算模型不支持。
- **执行状态**：未开始、进行、完成、失败、取消、中断；注明是否已发送及部分输出。
- **评分状态**：可评分、完成、失败、待复核、不适用；评分失败不自动生成0。

当前数据库已有部分状态/JSON扩展位置，但没有完整的下列报表投影。本轮不改表、状态或历史输出。未来投影需有版本；原始执行状态与报表排除原因都保留，不能为凑分数重写原事件。

### 计划数量与互斥计数

冻结模型/题目/重复/条件及准入证据后得到P。报告按以下优先级为每个逻辑项选一个主统计桶，使总数可对账；其他原因作为辅助标签，不把辅助标签再次相加：

| 桶 | 定义 |
| --- | --- |
| I | 题目/标准被正式确认有缺陷，不能用于当前质量结论；保留排除理由和版本 |
| U | 准入证据明确声明或实测不支持所需模型能力；再分自报/已验证，不在看到低分后临时改标 |
| B | 环境/授权/系统功能/评分器未实现或不可用而阻断；逐原因列明 |
| K | 因能力未知而未执行；未知不算unsupported |
| L | 正在准备、执行或评分且尚无终态的项；字段名in_progress_count，与未运行分开 |
| N | 其余尚未运行/未调度项；用户取消导致剩余项未发出也在此注明原因 |
| C | 尝试已经开始后取消/中断，未形成可评分完整输出 |
| T | 已尝试的模型/传输执行失败；代码程序自身错误另见编程口径 |
| E | 有完整输出但评分器故障或不可确认结果 |
| W | 人工复核未决、截断政策要求复核等 |
| S | 成功得到有效评分的项，包括答错项 |

`P = I + U + B + K + L + N + C + T + E + W + S`。多个原因共存时按表顺序取主桶，额外原因仍可查询；最终报告L须为0，否则标实验仍在进行，不能当作完成报告。桶是统计投影，不能抹掉原始attempt/错误阶段。例如单题因评分存储失败而实验failed，不能据此断言模型推理失败。

所有百分比同时显示分子/分母、P、有效评分覆盖率和上述数量。分母为0显示N/A而不是0%或100%。正式可比较集合在运行前固定；两模型支持集不同，分别给完整覆盖图和预先声明的共同子集，不能偷偷只挑双方都答对的题。

## 必须分别报告的指标

设`S_k`为类别k的有效已评分项数，`C_k`为其中满足该题完整判定的数量。这里C_k与上表取消桶C含义不同，报表字段分别命名correct_count和cancelled_count。

| 指标 | 分子/分母与范围 | 解释和限制 |
| --- | --- | --- |
| 基础功能通过率 | Level 1已尝试且技术验收可观察项中，满足预声明技术验收条件的项 / 全部这些项（含技术验收失败） | 标准请求/保存/解析/评分记录等闭环条件；模型答案错但正确判0可算应用闭环成功，答案正确率另列。未运行项不从视图消失，要同时显示覆盖率 |
| 基础题答案正确率 | Core60中正确的已评分题 / Core60有效已评分题 | Smoke基本题结果，不能代替Level 2能力正确率。当前一道真实开发题不能标整套60题100% |
| 能力正确率 | Level 2按类别的`C_k / S_k` | 主展示六类，不混入速度/费用/资源。只在同一固定可比较集合覆盖充分时可另列透明的等权题目正确率；公开类别与分母，不做跨维总分 |
| 难度通过率 | 每个已审阅难度d内正确项 / 该难度有效已评分项 | 同时按类别、公开/保留拆分。Core60没有hard时为N/A，不能补造困难结果 |
| 原生调用契约通过率 | 原生对象、工具名、参数结构/语义均符合契约的题 / 有效已评分调用契约题 | 用于不执行工具的Level 1；正文中的JSON或“已执行”叙述不能计原生调用 |
| 工具任务成功率 | 受控工具实际执行，且全任务依赖/参数/结果/状态断言满足的题 / 有效已评分工具任务题 | Level 2多步模拟任务；另列各步骤契约/调度/错误处理成功率，不把单个正确步骤当整题成功 |
| 编程测试通过率 | 全部必需断言、类型/输入不变及预算契约通过的题 / 有效已评分编程题 | 同时报告单题通过断言数/实际执行断言数；跨题不按断言数量加权，避免断言多的题支配结果 |
| 引用准确率 | 有效定位且确实支持相应声明的引用链接数 / 输出的全部引用链接数 | 不仅核对行号。零引用为N/A；应答题缺引用的后果在引用覆盖与任务判定中体现 |
| 引用覆盖率 | 被有效引用支持的必需事实数 / 该可答题的必需事实数 | 可答题没有引用时通常为0；本来不可答题无必需答案事实时为N/A，另看拒答正确率 |
| 延迟 | 首可见文字/首工具事件/服务响应/完整输出/应用全流程分别计时 | 报单位、计时来源、有效样本数、p50/p95、成功/失败/截断分组；不同口径不混算 |
| Token消耗 | Provider实际确认的输入/输出等计数，按请求/尝试/题/实验汇总 | 缺失null，估算另列；重复/预热若发生单独记录并计入实际消耗。最终累计usage不按每帧重复相加 |
| 不支持能力数量 | U总数及其模型、类别、能力、证据来源 | 分开advertised与probed；系统未实现/未开放不是U |
| 未运行及失败数量 | B/K/N/C/T/E/W/I分别列数量和原因，L单列进行中数量 | 不能只给成功样本，也不能把所有失败当模型答错或全记0 |

基础功能验收与错误处理控制夹具是两种轨道：对“正常完成”夹具，故障导致未满足验收条件算功能未通过；对“预期坏流/取消”夹具，正确保留部分并记录真实终态可算该错误处理检查通过。夹具协议不同，分别报告，不与真实模型答案正确率相加。

### 覆盖率与不完整结果

`A = P − I − U`是当前已定义且非已声明不支持的计划项，`S/A`为有效评分覆盖率；K/B/N等仍会降低覆盖率，不能借未实现功能提高看起来的完成程度。I/U也要显式展示，不能只显示A。声明不支持不等同独立实测，不能用不同U集合做未经说明的总体排名。

`C_k/S_k`是“已评分条件下的正确率”，不是对所有计划项的无条件正确率。覆盖不完整时默认禁止正式排序，只展示分项结果和缺失；正式发布需要预先约定的可比较集合完成验收。评分缺失不填0，也不能用分母缩小掩盖它。

同一道题多次重复全部保留，主口径使用每个逻辑项的首次尝试；重试后的完成率单列。Level 3按同一场景/重复做成对差异，样本量以场景/家族计，不将多个回合当多个独立样本。统计不确定性方法、重采样种子与次数在试验前固定，小样本不承诺稳定p95或显著提升。

## 各评分器的准入合同

### 中文和数学

确定事实/标签/槽位、字形及别名范围；问题若有多个合法答案，标准用可审计的允许集合或约束，而不是隐藏一个唯一字符串。别名/归一只对声明字段生效：不得全局lower导致化学式误判，也不静默把不同字符或单位都折叠。

整数、有理数、集合、单位和允许误差分别定义。给定具体ASCII格式时可严格解析，否则数值与格式分开；不执行模型提供的算式/代码。超过实现支持的数值范围先调整题目契约或采用规范整数文本，不能溢出/舍入后比较。需要解释的题用预先审阅rubric；无确定规则的回答进入人工复核，不由被测模型自行给自己评分。

### Python

Docker Linux控制器健康后才运行不可信提交。冻结镜像digest、Python版本、输入范围、资源/输出/时间界限和清理策略；缺环境为B，容器控制器/评分脚本故障为E。模型程序在健康沙箱中违反已声明契约、抛异常或超出题目资源预算是可判定的程序失败，与Docker服务崩溃分开。

参数以数据传入，函数名按题目契约定位；返回类型在JSON编码前检查，再按约定值语义比较。bool不是合格整数返回，tuple不能自动冒充要求的list；必要时递归检查元素类型。保存实参副本检测输入修改，纯函数不得依赖全局可变状态。只有题面定义了异常输入行为时才加入对应断言。

每道题的边界应有覆盖理由：空/单元素、零/负数/重复、最小最大合法值、Unicode/空白、顺序/输入不变，按题目适用，不机械套全。使用正确参考实现和已知错误实现控制：例如忽略大小写的回文实现、去重后才数偶数、错误修改输入。控制只能证明所覆盖错误被识别，不能宣称数学意义上穷尽所有错误。

### JSON

处理链为原始文本严格解码→检测重复键/多个值/非JSON数值→固定方言结构验证→领域语义断言。JSON Schema 2020-12的format断言能力需要明确配置，不能以type=string或正则代替日历验证。[规范](https://json-schema.org/draft/2020-12/json-schema-validation)

对象键顺序无关、数组顺序按契约、null与缺失不同、布尔与数字不同。整数的数学语义包括1与1.0；若题目另有词法格式要求，单独评分而不是偷偷改变Schema语义。[JSON Schema数字类型](https://json-schema.org/understanding-json-schema/reference/numeric)

拒绝重复键是本协议的严格政策，需在解码时检查；规范指出重复名称的接收行为可能不同，不能解析后忘掉重复信息。[RFC8259](https://www.rfc-editor.org/rfc/rfc8259#section-4)

验证器应有公开的支持词汇/方言和一致性检查，未知关键词或未支持方言是评分配置问题，不应静默忽略后给模型通过。冻结schema、验证器/版本、format政策及语义断言版本；当前example_matches仅用于作者示例的小词汇检查，不能直接当通用运行评分器。

### 原生工具

必须读取Provider响应中的原生调用字段及流式增量，保存工具名、结构化参数、索引/关联ID和轮次；内容为空但有有效调用是合法情况。不能让当前“空文字即失败”的文字生成规则直接处理工具轨道。[Ollama协议](https://docs.ollama.com/capabilities/tool-calling)

调用对象存在、名称合法、参数Schema正确、参数语义正确、调度与依赖正确、最终任务成功分开判定。临时call ID不与固定字面值比对，但必须能正确关联调用和工具结果；独立调用顺序允许变体，有依赖时按顺序校验。多步工具只作用于受控重置的模拟状态，任何实际文件/网络/生产知识副作用都不属于本测试的授权。

Level 1的五题目前不执行工具，因此只能测对象契约；Level 2在模拟执行后才可报告“工具任务成功率”。模型写出与标准一致的普通文本JSON仍不能算原生调用成功。

### RAG和认知证据

将可答性、事实正确、引用位置、语义支持、证据覆盖及冗余分开。标准建立claim_id与允许证据组合的对应，不只列一个精确跨度。足够证据的较宽跨度可有冗余成本，但不能直接等同错误引用；不允许宽到掩盖矛盾的引用自动过关。

不可答响应采用明确结构，拒答原因与不补造事实均验证，不能靠“任意非空说明”通过。冲突题同时验证冲突状态及双方事实/证据；版本题有固定as_of、有效性和权威规则。人工审阅争议时G=needs_review，不能伪装确定语义评分。

Level 3保留E/R/C/Y/G证据链。检索候选不足、上下文装配丢证据、证据充分后的回答错误、评分器错误分别报告；不可答或授权禁止取材是预期条件，不强归成检索错误。来源/知识快照、版本对照和A/B/O设计见[认知方案](benchmark-tiers-design.md)。

## 性能与资源口径

客户端用单调时钟记录开始发送、收到头、首个有效可见文字/原生工具事件、终帧和落盘/评分完成。时间戳事件不能直接回填精确首字延迟；Header延迟不是TTFT，工具首事件也不是首字。失败时保留已观测阶段和部分消耗，未出现的首输出为null，不填0。

Provider计数保持来源、单位、最终确认状态及缺失原因。服务端eval_duration和客户端端到端时间分别存；生成速度若定义为输出Token/服务端生成秒数，就必须同时显示这两个有效字段，否则N/A。不同模型分词器的Token不是相同文字量，禁止据此误称同文字吞吐。

本地加载/保温、设备、并行度、可见thinking设置和停止原因作为条件记录。只记录Provider可见字段，不声称获得隐藏思维链。现有Frame字段尚不等于完整客户端计时或硬件采集，本方案没有新增这些实测。API不存在的计数不能从字数或总时长猜造。

## 评分发布与审计门槛

每个评分器先做独立控制包，和模型能力题分开：

| 类别 | 至少应验证的控制关系（待实施） |
| --- | --- |
| 数值/中文 | 正确值/允许别名接受；错误值/超范围/声明外格式拒绝；多合法解按契约接受 |
| Python | 已知正确实现通过；被边界区分的错误实现失败；类型、输入修改、资源限制与容器故障分开 |
| JSON | 调换对象键不改结果；错误类型/缺失/额外字段/数组乱序/重复键/非法日期按各自阶段拒绝 |
| 工具 | 真正tool_calls可接受，即使无文字；伪装文字JSON拒绝；错参数/关联/依赖/越权分开标记 |
| RAG | 有效替代证据可接受；正确行号但不支持声明不能通过；拒答不能夹带编造；无引用分母正确 |
| 状态/汇总 | U/B/K/L/N/C/T/E/W/I/S数量可对账；进行中与最终快照均检查；无分母N/A；重试不挑最高；评分器失败不生成模型0分 |

控制包需要正确/错误预期由独立审阅确定，评分实现版本和规则hash冻结。外部标准或oracle也会出错，分歧未解决不把题标为已通过；修订记录可追溯。

报表至少含题目/规则/模型/知识快照身份、原始输入/输出、实际原生调用、精确请求、独立指标、各分母、状态/错误阶段和全部尝试。公开隐藏集报告按访问策略去除题干/答案/私有断言，授权审计保留完整明细，不以导出泄漏隐藏题。

Core60历史报告仍按其原版本显示。重评分新增版本/hash与结果，不修改旧输出；跨评分版本比较先选择同一口径并明确是否已复算。这里的复算/汇总功能仍需后续实现，本轮不运行或生成任何正式能力分数。
