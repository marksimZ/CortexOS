## D2b-0：环境准备与验收

1. **安装范围已确认**：微软官方稳定版WSL2；本机引导命令退出1后改用官方稳定MSI，不额外安装Ubuntu。Docker官方x86_64 Desktop按当前用户安装、WSL2/Linux后端；下载Python3.13官方基础镜像。按实际安装器支持的参数，将Docker镜像/虚拟磁盘放入`D:\CortexOSRuntime\DockerData`，应用按官方当前用户默认路径安装。下载与镜像均记录真实版本/hash，不硬编码未确认发行版或Image ID。
2. **执行方式**：只从官方来源下载，安装前校验Windows签名/发布者及实际文件hash。Docker采用`install --user --backend=wsl-2`，按当前安装器支持添加数据目录参数；不安装Windows容器，不启用2375远程未认证端口，不将个人目录或Socket挂进容器。若需要协议确认/系统UAC，由用户处理；需要重启时报告并停止依赖操作，不自动重启。
3. **就绪检查**：实际`wsl --version`、`wsl --status`、`docker version`、本地context endpoint及服务端OSType=linux。CLI存在不等于后端可用。安装/启动记录与代码测试结果分开。
4. **镜像绑定**：明确下载Python3.13镜像后，用`docker image inspect`取得实际sha256 Image ID、OS/架构/RepoDigests。沿用现有`benchmark/python.rs`的`environment`、`policy`、受限create/inspect/score/cleanup，评分运行不自动拉镜像。
5. **必要实测**：非root、只读root、无网络、CPU/内存/PID上限、总时间/单断言时间/输出上限、无宿主挂载/Socket；正常、错误答案、超时、取消和清理场景均记录实际结果。只运行受控验收输入，项目仓库仍不执行。必要时修复原控制器根因，不新建重复Docker运行器。
6. **补验历史阻断**：就绪后以固定Core60 v2和当时实际可用的模型身份，新建独立Python题计划。原20条docker_unavailable保留，新的调用/评分与旧计划关联，不能通过改写原记录制造通过。实际缺少的模型或环境按缺失报告，不自动下载新模型。

官方依据：[Docker Windows安装与参数](https://docs.docker.com/desktop/setup/install/windows-install/)、[微软WSL安装](https://learn.microsoft.com/en-us/windows/wsl/install)、[WSL命令的no-distribution选项](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)。本轮已实际打开核对。容器Python版本沿用现有合同3.13，最终镜像ID以本机实取为准。
